# 🍔 麦麦省钱点单助手 · mcd-savings-assistant

> 会算账的麦当劳点单专家：一键领券 · 自动用最优券 · 智能搭配 · **省钱榜单** · 卡路里可视 · **结算舱** · **外送到家（对话内建地址）** · **麦麦摇摇乐** · 附近门店导航 · DIY 自由搭 · 一键下单

基于 **麦当劳中国 MCP**（`https://mcp.mcd.cn`）能力开发的可交互可视化 Skill。
它不只是一个聊天机器人——它会把 MCP 返回的真实菜单、优惠券、营养与门店数据，渲染成一个**可点击、可勾选、实时算价算热量**的 HTML 可视化点单助手。

## ⚡ 30 秒看到效果（无需 Token、无需配置、不用联网）

| 方式 | 怎么做 | 需要准备 |
|---|---|---|
| **① 在线打开（最快）** | 直接访问 <https://huangxxuan.github.io/mcd-savings-skill/> | 只要一个浏览器 |
| **② 离线打开（断网也能用）** | 下载本仓库（`Code` → `Download ZIP`）→ 解压 → **双击 `assets/order-assistant.html`** | 只要一个浏览器 |
| **③ 实时数据** | 按下方「安装与使用」配好 MCP，让 Agent 用当前价格重新生成页面 | MCP Token |

> ⚠️ **不要直接在 GitHub 网页上点 `order-assistant.html`**——GitHub 只会显示源代码，不会渲染页面。请用 ① 的在线地址或 ② 的方式打开。
>
> 📦 页面数据来自 `assets/data.js` 快照（**2026-10-25 10:30 抓取**，含 114 个餐品 / 5 家门店 / 9 张券 / 64 条热量），
> 页面自身**不发起任何接口请求**，所以断网也能完整演示（唯一的外链是摇摇乐摇中后的那张餐品图，
> 来自麦当劳 CDN，断网时会自动降级成 emoji）；想看实时价格请走 ③（需要你自己的 MCP Token）。
>
> ⏰ **券的有效期会被复核两次，都不依赖快照**：
> ① **生成数据时**（`build_data.py`）按当时的当前时间剔掉过期/未生效的券，所以省钱榜单里不会出现
> 「今天下不了单的券后价」；② **你打开页面时**再按浏览器当前时间算一遍，页面这边覆盖快照放久的情况。
> 过期券自动退出计价、在券面板标「已过期 / 未生效」、榜单里改用现价重算，提醒里的「剩余 N 天」
> 也按当前时间重新倒计时。价格与热量仍以快照时间为准。

| 🎨 **DIY 自由搭**   | 全菜单勾选，套餐内可替换项自由换，实时联动总价与总热量                                              | `query-meal-detail`                                                                                        |

> ⚠️ **数据口径说明**：麦当劳 MCP 的 `list-nutrition-foods` 只覆盖约 158 种常见餐品，新品/组合餐（如「龙焰芝士棒鸡腿堡」「奶香大米派」「BFF 四宫格小食盘」）无官方热量数据。匹配分三档，页面如实标注——**不编造任何营养数据**：
>
> | 档位   | 规则                                       | 页面显示          | 实测数量    |
> | ---- | ---------------------------------------- | ------------- | ------- |
> | 精确   | 名称归一化后完全一致/互相包含                          | `🔥 391 kcal` | 58 / 114 |
> | 近似匹配 | 先做规格归一（去掉「中杯/大杯/热/冰/™」），仍不中再用 2-gram 相似度 ≥ 0.45 兜底（如「灰焰圆筒」→「圆筒冰淇淋」） | `🔥 ≈93 kcal` | 6 / 114 |
> | 未匹配  | 三档皆不中                                    | `热量待核`        | 50 / 114 |

> 💡 **「原价 / 立省 / 应付」的口径**（页面底部 HUD 与省钱榜单同一套算法，已用 `calculate-price` 逐分对账）：
> **原价** = MCP 返回的划线参考价（`origin`，没有划线价时用现价）；
> **应付** = 商品实付（现价合计 − 券抵扣）**+ 配送费**；
> **立省** = 原价 − 商品实付，**同时包含官方直降与券**，但**不含配送费**——配送费不是商品。
>
> ⚠️ **划线价是「参考价」，不等于结算优惠**：`query-meals` 的 `originalPrice` 是营销参考价，
> 而 `calculate-price` 对套餐类商品返回的 `productOriginalPrice` 往往就等于现价、`discount: 0`
> （麦香鸡套餐 40.5 → 28，核价原价 28、优惠 0）。所以页面上的「立省」标注为**参考划线价**，
> 真实优惠只有 `calculate-price` 的 `discount` 才算数。
>
> 🪪 **麦金卡商品会双价显示**：菜单里带 `麦金卡` 标签的 14 个商品（四件套 / 随心选 / BFF 双人餐），
> 菜单价是**会员价**；没有该权益的账号，结算按划线价收：
>
> | 商品 | 菜单价 | 无麦金卡时结算 | 差 |
> |---|---|---|---|
> | 板烧鸡腿堡四件套 | ¥28 | **¥57** | +29 |
> | BFF 四宫格双人餐 | ¥62.9 | **¥122.5** | +59.6 |
>
> 页面会在卡片上同时露出两个价；结算舱的金额明细里会多出两行 ——
> 「麦金卡 N 件 · 按会员价算」+「若非会员，实际为 ¥X」，HUD 也会写「含 N 件麦金卡价，非会员需多付 ¥X」，
> 所以「应付」旁边永远能看到两个数字，不会只看到一个偏低的会员价。
>
> 🚚 **配送费不臆造**：页面**不会**写死一个「配送费 6 元」。它只认门店返回的真实字段
> （`fee` / `min` / `freeOver`，含常见别名）；门店没返回时，HUD 写「商品 ¥X · 不含配送费（以结算页为准）」，
> 应付就等于商品实付。门店面板顶部可切「🛵 外送到家 / 🍽 到店自取」，自取时配送费与起送门槛都是 0。
> 外送也不需要你先去麦当劳 App 填地址：页面里填一次（存 `localStorage`），AI 会拿着它调
> `delivery-create-address` 建档 → `delivery-query-stores` 查可配送门店 → 核价 → 下单。
> 拿到外送门店后重跑 `build_data.py`，真实配送费与起送门槛就会写进 `deliveryStores`。
>
> 🎟️ **券从哪来、能省多少，全部来自真实核价**：
> `我的卡包`（`query-my-coupons`）、`门店/活动券`（`query-store-coupons`）、
> `可领券`（`available-coupons`）三个来源合并去重后分组展示，每张券都标了来源。
> `build_data.py` 会**逐张调 `calculate-price`** 验证，把 `realOk / realDiscount / realPay` 写进数据。
> 因此你能看到这些「标称能省、实际不行」的情况被如实标出：
>
> - `新人专享-中杯美式7折`（券后价 13.3）——对菜单里的美式返回 **600012 促销规则不支持该商品**；
>   它真正能用的是自带的券专属 SKU `9900000119`。而美式现价才 11.9，用这张券反而贵 1.4 元。
> - `人气麦旋风买一送一`——`beTypes=[4]`，到店核价直接 **600012 当前优惠券不可用**。
> - `19.9元王牌炸鸡任选2`——真实 SKU 是 `9900016534`（**不在菜单里**），核价 23.8 → 19.9，
>   **真实只省 ¥3.9**，不是标题暗示的 9.6。这个 SKU 已被补进菜单，否则用户拿着券却买不到东西。
>
> 算不了的券会明确标「需在结算页核销」，**不参与自动用券、也不计入立省**——宁可少报，不报假账。
> 另外：**一张券只对 1 件生效**（`quantity=2` 带券核价时接口会把数量截成 1），多件请拆开核价。

## 🏗️ 技术实现

- **Skill 层**：`SKILL.md` 定义触发词与九阶段工作流（定位门店/建外送地址 → 领券 → 菜单与营养取数 → 场景搭配 → **省钱榜单** → 确认下单 → **凑单 + 麦麦摇摇乐** → 不错过提醒 → 商城订单），约束模型必须真实调用 MCP、禁止臆造数据。
- **数据层**：每次会话拉取一次 `query-meals` + `list-nutrition-foods`，合并为本地缓存映射。
- **推荐算法**：预算/热量约束下的组合枚举（贪心 + 剪枝），本地初筛后仅对 Top 3 调用 `calculate-price` 精算，单次会话 MCP 调用 < 10 次，规避 600 次/分钟限流。
- **省钱榜单算法**：`build_savings()` 用「现价 / 划线原价 / 真实核价过的券」枚举主餐 × 饮品（× 小食），
  逐条套最优券后按 5 个维度排序。**券后金额全部来自 `calculate-price`**：
  `verified_coupon_rules()` 只收核价成功（`realOk`）且 `realDiscount > 0` 的券，抵扣额直接用接口返回值，
  券只作用在它核价时真正吃下的 SKU（`skus[].code`）上 —— 不用券 Title 猜面额，也不按名字凑单。
  券的 `applyTo` 与 `skus` 常常不一致（实测「9.9元中杯冰美式」`applyTo=507411`、`skus=9900000119`），
  以 `skus` 为准。组合行里抵扣按**现价**算（`Σ券管 SKU 现价 − 券后价`），避免把官方直降重复计一次。
  「四件套 / 随心选」一族的菜单价是麦金卡会员价，榜单行会带 🪪 标记 + 非会员实付，且不参与「今日最优解」。
  支持 `build_data.py --rank` 离线重算，不联网、不产生编造数据。
- **预算分档算法**：旧版在生成组合时用四处硬编码（主食 `≤45`、二件套 `>50` 丢、三件套 `>55` 丢、券后 `≤45` 砍）
  把价位两端挖成了空档 —— 菜单最低 ¥3 却一个都进不了榜，`≤¥20` 永远是空列表，`≥¥100` 根本不存在。
  现在全价位都生成（约 2100 条：单品 / 单个套餐 / 主食+小食 / 主食+饮品 / 三件套 / 套餐拼单），再由 `budgets` 分档**挑**最优：
  ① 预算用足（只在 `[cap×0.7, cap]` 内挑，20 元档放宽到 0.6）；
  ② 必须是一顿饭（20 元档只要求有主食，30/50 要含饮品 —— 套餐本身含饮品，按 `kind="set"` 直接放行）；
  ③ 递进（这一档必须比上一档多花至少 20%，否则「有 50 块」会被答成上一档的同一单）；
  ④ 排序按「省下的钱 → 省的比例 → 每元热量」，不能只按每元热量，不然省 40% 的两件套会因为「热量待核」被打成 0 分落选；
  ⑤ **麦金卡价不能当预算答案**（四件套菜单 28 / 非会员 57，若「预算 30」档答它，没开卡的人到结算页直接超预算），
     所以先在「人人可用」的价里挑，整档都是会员价商品时才退回并在卡片上标明。
  `≥¥100` 是**套餐拼单**，不是单品堆叠：把套餐当原子单位，只枚举「2 个大套餐 / 1 套餐 + 单品 / 3 个三件套」三种结构，
  按「套餐件数占比 → 预算贴近度 → 省额」排序。旧版从单品池拼 6 件，报出的是
  「培根安格斯 + 芝士安格斯 + 可乐 + 美式 + 苹果片 + 派」—— 6 个全单点，同预算买套餐能多一件还更便宜。
  **`kcal > 0` 不再作为上榜门槛** —— 旧版用它一刀切，把 55 个「热量待核」商品全部除名。
- **套餐营养口径**：`query-meals` 对「四件套 / 三件套 / 套餐」返回的 `kcal / protein` **只等于主堡单品**
  （板烧四件套 391 = 板烧鸡腿堡 391；培根安格斯 707 = 单品 707），薯条 / 可乐 / 派一粒卡没算。
  这会让一个 1000+ kcal 的套餐在「健身 / 控卡」场景里被当成 539 kcal 的高蛋白餐推出去。
  修法：以「套餐 kcal == 同名主堡单品 kcal」作为硬证据判定「只算了主堡」，再按菜单里薯条 289 / 可乐 147 / 派 232
  的**官方值**相加，标 `setKcalEstimated` + 写明构成（`官方只给主堡 391 kcal，余下按菜单 薯条 289 + 可乐 147 + 派 232 估算`）。
  「500大卡套餐」这类官方给整份的不重复相加；「随心选 / 双人餐 / 拼盘」构成不明，标「营养未含配餐」，不编数字。
  幂等：已补过的不会二次相加。
- **场景推荐三条硬规则**：① 套餐不配饮品（四件套已含饮料，再叠一杯奶铁就是重复点单）；
  ② 报价用真实结算价（29 元的三件套是现价，28 元的四件套是会员价，两种不能混着报）；
  ③ 三个方案按「主品 core 名 + 件数」去重 —— 旧版会给「板烧单品 / 板烧四件套 / 板烧三件套」配同一杯奶铁，
  同一个堡换三种包装，卡路里还完全一样。健身场景另有两条：方案蛋白 ≥ 25g，且排除奶铁 / 拿铁 / 雪顶 / 新地。
  「悦己养颜」判分类时**不看分类名**（菜单里有个分类叫「小食甜品/其他」，一匹配「甜品」二字，薯条鸡块全被打上养颜标签）。
- **可视化层**：单页 HTML，纯原生 JS 实现状态驱动渲染——选品、券开关、模式切换、门店选择全部实时联动「原价 / 立省 / 应付 / 总热量」。
- **闭环**：用户确认 → `create-order` → 麦当劳官方支付链接（本项目不接触任何支付信息）。

## ❓ 常见问题（FAQ）

**Q1：点开页面一片空白 / 只有一个深色背景？**
`order-assistant.html` 与 `data.js` **必须在同一个目录**。只下载了 HTML 就会白屏——请整个仓库一起下载，或直接用[在线版](https://huangxxuan.github.io/mcd-savings-skill/)。

**Q2：页面上的价格和店里不一样？**
页面读的是 `assets/data.js` 快照（**2026-10-25 10:30 抓取**），不是实时价格。要拉最新数据：
```bash
MCD_MCP_TOKEN=你的Token python3 scripts/build_data.py
```
跑完刷新页面即可。

> 🍟 **一条命令产出的是完整数据**：门店 / 菜单 / 营养 / 券（逐张 `calculate-price` 核价）/ 活动 /
> **套餐营养补全** / 五大场景 / **省钱榜单（含四档预算）** / **35 个 Tools 清单**，全部一次性写进
> `data.js`。不需要再补跑 `--rank` 或 `--repick`（那两条只是离线重算用的）。
> 时段提示：**早餐时段（约 10:30 前）菜单里没有三件套/四件套**，想拿到完整套餐请在正餐时段跑。

> ⏰ **快照放久了，券都过期了，页面还算得对吗？** 算得对。价格与热量以快照为准，但**券的有效期是
> 页面按你打开时的当前时间现算的**：过期 / 未生效的券自动退出计价并在券面板标出来；省钱榜单里依赖
> 该券的行改用现价重算并沉到队尾；「不错过」里的「剩余 N 天」按当前时间重新倒计时。所以一份放了几
> 天没更新的快照，也不会算出一个今天核销不了的价格。要最准仍建议重跑一次 `build_data.py`。

**Q3：调用 MCP 报 401？**
Token 失效或没带对。去 <https://open.mcd.cn/mcp> 重新生成，确认 Header 是 `Authorization: Bearer <token>`。

> 🔧 脚本已经做了容错：`MCD_MCP_TOKEN` 里带不带 `Bearer ` 前缀都能跑（脚本自己会补，重复前缀会被
> 自动去掉）。所以 401 基本只剩一个原因 —— **Token 本身过期了**，去控制台重新生成即可。

**Q4：报 429 Too Many Requests？**
触发限流（600 次/分钟）。本项目正常使用不会超——菜单与营养数据每次会话只拉一次并本地缓存，只对 Top 3 组合调 `calculate-price`。若确实超了，等 1 分钟再试。

**Q5：点了「一键领券」，页面还显示「未领取」？**
`auto-bind-coupons` 成功后，查询接口有**短暂延迟**。等几秒刷新，或重跑 `build_data.py --claim`。这不是领取失败。

**Q6：为什么不直接在 GitHub 上点 `order-assistant.html`？**
GitHub 只显示源代码，不渲染 HTML。请用[在线版](https://huangxxuan.github.io/mcd-savings-skill/)，或下载后本地双击。

> 📄 想直接在线阅读 / 拉取 Skill 定义：<https://huangxxuan.github.io/mcd-savings-skill/SKILL.md>
> （仓库根目录放了 `.nojekyll`，GitHub Pages 才会把 `SKILL.md` 原样当静态文件返回；
> 否则 Jekyll 会因为文件头的 YAML front matter 把它渲染成 `SKILL.html`，导致 `SKILL.md` 404。）

**Q7：应付金额为什么和「商品金额」不一样？配送费哪来的？**
页面**不写死配送费**。它只读门店返回的真实字段；门店接口没给，就不加钱，
HUD 直接写「不含配送费（以结算页为准）」。想看含配送费的准确金额，
复制页面底部的点单指令让 Agent 调 `calculate-price` 核价——那才是最终价。
切到「🍽 到店自取」，配送费和起送门槛都归零。

**Q8：别人装上这个 Skill，看到的是我的券吗？怎么换成自己的？**
会。所以你一打开券面板看到的第一个东西就是横幅：
**「这是快照账号 ****8352 的券，不是你的」**，后面跟着快照时间、`9 张券 / 4 张现在能用`，
以及「📋 用我自己的券」按钮（点了直接复制换券命令）。
快照里只有券名、面额、有效期与核价结果，**不含券码与会员号**（见文末「🔐 安全与密钥说明」）。
换成自己的只需一条命令——用**你自己的 Token** 重跑：
```bash
MCD_MCP_TOKEN=你的Token python3 scripts/build_data.py --claim
```
`--claim` 会先调 `auto-bind-coupons` 把能领的券领到你自己的卡包，再抓门店券、菜单、营养与账户余额。
`data.js` 一换，页面上所有券、金额、省钱榜单**自动跟着变，不需要改一行代码**。

**Q8.5：我怎么知道系统自动用了哪张券？想换一张怎么办？**
选好商品后，券面板最上面会出现一张卡，一行写完三件事：

> 🎟️ **已自动用券：新人专享-中杯美式7折**
> 省 **¥5.70**　应付 ¥13.30　次优「9.9元中杯冰美式」只能省 ¥0

选了哪张、省了多少、为什么不是别的那张（次优对照），全在这一行。
规则是「在所有能用的券里挑省得最多的一张」，你不用手点。想换就点下面任意一张券 ——
手动点过就退出自动模式；HUD 旁「自动用券: 开/关」可以整体切回来。
如果这一单用不上券，这张卡会直接列出「哪张券管哪几样商品」，照着点就会自动抵扣。

**Q8.6：右栏那个「MCP Tools」是干什么的？**
它是这套 MCP Server 的**能力清单**，共 35 个工具、6 组（门店与菜单 / 优惠券 / 核价下单 / 外送 / 会员积分商城 / 活动抽奖团餐）。
点组名展开，每个工具都有三样东西：**用途**、**必填参数**、**可直接执行的调用样例**。

- 单条复制：点工具右侧「复制」，拿到 `query-meals({"storeCode":"1420762","beType":1,"orderType":1})` 这样的调用，
  直接粘给任何支持 MCP 的 Agent 就能跑；
- 一键复制全部：右上角「复制全部」，产出完整 Markdown（分组 + 每个工具的参数与样例），
  适合贴进系统提示、做二次开发、或给同事看「我们接的 MCP 到底能干什么」；
- 标 **`写`** 的是写操作（`create-order` / `cancel-order` / `auto-bind-coupons` / `mall-create-order` /
  `party-order-create` / `draw-lottery` / `delivery-create-address`），会真实下单、领券或抽奖，执行前务必确认。

清单里 `query-promotions`、`query-survey-coupon` 这两个官方 README 没列，但 `tools/list` 里确实有、本项目也实测调通过。

**Q8.7：门店卡上写着「未抓菜单 · 仅供参考」，不能直接切过去吗？**
不能，而且上一版「📍 门店 // 点击切换」是**假的**：点一下会弹「已切换门店」，
但菜单、券、榜单全都还是快照那一家的数据 —— 换了等于没换，属于骗人，已删除。

原因很实在：一份菜单要配一整套核价（`query-meals` + 逐张券 `calculate-price` + 榜单重算），
多抓一家店就是多一倍请求与体积。所以本页只深抓**一家**店的完整数据，其余门店诚实地标成
「未抓菜单」并只提供导航。要换店点 `🔁 切店指令`，复制出来的是：

```bash
MCD_MCP_TOKEN=你的Token python3 scripts/build_data.py --store-code 1420659 --store-name "麦当劳深圳金拱门食品有限公司(禹洲广场)餐厅"
```

跑完刷新页面，菜单 / 券 / 榜单 / 场景全部换成那家店。

**Q8.8：为什么切到「外送到家」后价格变了？**
因为外送门店的菜单本来就是**另一套货号和另一套价格**。实测同一家商圈：

| 商品 | 到店货号 / 价格 | 外送货号 / 价格 |
|---|---|---|
| 板烧鸡腿堡 | `1406` ¥23.5 | `901406` ¥27.0 |
| 苹果片 | ¥7.0 | ¥7.5 |

所以外送模式整池换成外送门店的菜单（115 个商品），配送费取 `calculate-price` 的
`deliveryPrice` 实测值（本店 ¥6.00），打包费取 `productList` 里的「打包服务费」。
如果你拿外送订单套到店的货号，接口会返回「商品 0 元、只收 6 元配送费」——这正是修这个问题的起因。

**Q8.9：外送模式下，榜单和场景为什么还写着「到店自取口径」？**
因为榜单里每一行都带着**券**，而券是按到店门店核价的（`beType=1`）。在外送模式下直接套用，
就会出现「榜单 ¥22.9、结算 ¥27」这种对不上的账。所以页面顶部会挂一条提示，
点任意一行会**自动切回「到店自取」再点单**，并在提示里写明「已从外送切回」。

**Q9：「不错过」板块里有的能点、有的点不了？**
规则是固定的：能在菜单里找到对应商品的券 → 可点，点了在菜单里高亮并闪烁；
待领券 → 点了跳到优惠券面板；找不到对应单品的 → 不可点，会写明「该券无对应单品，需在结算页核销」。
免费券如果只能模糊匹配到某个商品，会打上「近似」标记，**只用于定位，不会拿来抵扣金额**——
否则就会出现「免费券却按另一个商品的价格收你钱」。
这个板块的定位只有一件事：提醒你**快过期的券、能领没领的券、今日活动**，别错过。

**Q10：想点外卖送到家，是不是得先去麦当劳 App 里填收货地址？**
**不用。** 在页面「📍 门店」面板切到「🛵 外送到家」，会直接出现收货地址表单
（城市 / 联系人 / 性别 / 手机号 / 地址 / 门牌号）。填完存在你自己浏览器的 `localStorage` 里，
并自动生成一段下单指令；把它交给 AI，AI 会按顺序执行：

```
delivery-create-address  → 用你填的 6 个字段建档，拿到 addressId
delivery-query-stores    → 按 addressId 查可配送门店，拿 storeCode + beCode + 真实配送费
calculate-price          → orderType=2 / beType=2 核价
create-order             → 带 addressId + beCode 下单，返回支付链接
```

> 注意：外送门店要「按地址」查，所以页面在拿到外送门店前**不会**用附近门店顶替
> （到店与外送是两套门店编码，混用会下单失败）。建档后重跑一次
> `python3 scripts/build_data.py`，真实配送费与起送门槛就会写进 `data.js`。

拿到它的人**必须自己去申请一个 Token** 才能调用麦当劳 MCP（见上方「🚀 安装与使用 → 第 1 步：申请 MCP Token」）。

| 项目 | 说明 |
|---|---|
| Token / 密钥 | 仓库内 **0 处**。配置文件 `mcp-config.example.json` 只有 `${MCD_MCP_TOKEN}` 占位符，真实值走环境变量或 MCP Client 的本地配置 |
| 个人信息 | 快照已脱敏：`account.accountId`（麦享会会员号）只留后 4 位；`myCoupons[].couponId` / `couponCode`（卡包券核销凭证）**不写入** |
| 收货地址 | 只存在你自己浏览器的 `localStorage` 里，**不上传、不进仓库**。快照里的 `delivery` 只保留「可配送门店 + 配送费 + 打包费」，地址 / 联系人 / 电话 / `addressId` 由 `sanitize_snapshot()` 强制剥离（连测试地址也不会进公开仓库） |
| 防误提交 | `.gitignore` 已排除 `.env` / `.env.*` / `*.token` / `*.key` |

**你自己用的时候：**

```bash
# 1) 申请 Token：https://open.mcd.cn/mcp  → 控制台 → 激活 → 复制
export MCD_MCP_TOKEN='你的Token'      # 只放环境变量，不要写进任何文件
```

> 提交前请自己再确认一遍：`grep -E 'github_pat_|Bearer [A-Za-z0-9]|accountId' assets/data.js`
