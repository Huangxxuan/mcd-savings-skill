# 🍔 麦麦省钱点单助手 · mcd-savings-assistant

> 会算账的麦当劳点单专家：一键领券 · 自动用最优券 · 智能搭配 · **省钱榜单** · 卡路里可视 · 附近门店导航 · DIY 自由搭 · 一键下单

基于 **麦当劳中国 MCP**（`https://mcp.mcd.cn`）能力开发的可交互可视化 Skill。

- **字体**：Space Mono（展示字，等宽终端感）+ JetBrains Mono（等宽数字 `tabular-nums`）+ Noto Sans SC（中文正文）。
- **CSS 3D**：`perspective` + `transform-style: preserve-3d`，卡片悬停沿 X/Y 轴倾斜、按下物理回弹，祝福卡 `rotateY(180deg)` 翻转。
- **氛围层**：四层叠加——网格底纹 + 径向霓虹光晕 + CRT 扫描线 + 暗角。
- **入场编排**：一次性错峰揭示序列（3–6 组，间隔 90ms），而非零散微交互。

> ⚠️ **数据口径说明**：麦当劳 MCP 的 `list-nutrition-foods` 只覆盖约 158 种常见餐品，新品/组合餐（如「龙焰芝士棒鸡腿堡」「奶香大米派」「BFF 四宫格小食盘」）无官方热量数据。匹配分三档，页面如实标注——**不编造任何营养数据**：
>
> | 档位   | 规则                                       | 页面显示          | 实测数量    |
> | ---- | ---------------------------------------- | ------------- | ------- |
> | 精确   | 名称归一化后完全一致/互相包含                          | `🔥 391 kcal` | 53 / 100 |
> | 近似匹配 | 先做规格归一（去掉「中杯/大杯/热/冰/™」），仍不中再用 2-gram 相似度 ≥ 0.45 兜底（如「灰焰圆筒」→「圆筒冰淇淋」） | `🔥 ≈93 kcal` | 7 / 100  |
> | 未匹配  | 三档皆不中                                    | `热量待核`        | 40 / 100 |

> 💡 **「原价 / 立省 / 应付」的口径**（页面底部 HUD 与省钱榜单同一套算法，已用 `calculate-price` 逐分对账）：
> **原价** = MCP 返回的划线参考价（`origin`，没有划线价时用现价）；
> **应付** = 商品实付（现价合计 − 券抵扣）**+ 配送费**；
> **立省** = 原价 − 商品实付，**同时包含官方直降与券**，但**不含配送费**——配送费不是商品。
>
> ⚠️ **划线价是「参考价」，不等于结算优惠**：`query-meals` 的 `originalPrice` 是营销参考价，
> 而 `calculate-price` 对套餐类商品返回的 `productOriginalPrice` 往往就等于现价、`discount: 0`
> （麦香鸡套餐 40.5 → 28，核价原价 28、优惠 0）。所以页面上的「立省」标注为**参考划线价**，
> 真实优惠只有 `calculate-price` 的 `discount` 才算数。
>
> 🪪 **麦金卡商品会双价显示**：菜单里带 `麦金卡` 标签的 14 个商品（四件套 / 随心选 / BFF 双人餐），
> 菜单价是**会员价**；没有该权益的账号，结算按划线价收：
>
> | 商品 | 菜单价 | 无麦金卡时结算 | 差 |
> |---|---|---|---|
> | 板烧鸡腿堡四件套 | ¥28 | **¥57** | +29 |
> | BFF 四宫格双人餐 | ¥62.9 | **¥122.5** | +59.6 |
>
> 页面会在卡片上同时露出两个价，并在 HUD 写「含 N 件麦金卡价，非会员需多付 ¥X」。
>
> 🚚 **配送费不臆造**：页面**不会**写死一个「配送费 6 元」。它只认门店返回的真实字段
> （`fee` / `min` / `freeOver`，含常见别名）；门店没返回时，HUD 写「商品 ¥X · 不含配送费（以结算页为准）」，
> 应付就等于商品实付。门店面板顶部可切「🛵 外送到家 / 🍽 到店自取」，自取时配送费与起送门槛都是 0。
> 外送还需要账号里有收货地址（`delivery-query-addresses`），没有时页面会直接提示去 App 添加。
>
> 🎟️ **券从哪来、能省多少，全部来自真实核价**：
> `我的卡包`（`query-my-coupons`）、`门店/活动券`（`query-store-coupons`）、
> `可领券`（`available-coupons`）三个来源合并去重后分组展示，每张券都标了来源。
> `build_data.py` 会**逐张调 `calculate-price`** 验证，把 `realOk / realDiscount / realPay` 写进数据。
> 因此你能看到这些「标称能省、实际不行」的情况被如实标出：
>
> - `新人专享-中杯美式7折`（券后价 13.3）——对菜单里的美式返回 **600012 促销规则不支持该商品**；
>   它真正能用的是自带的券专属 SKU `9900000119`。而美式现价才 11.9，用这张券反而贵 1.4 元。
> - `人气麦旋风买一送一`——`beTypes=[4]`，到店核价直接 **600012 当前优惠券不可用**。
> - `19.9元王牌炸鸡任选2`——真实 SKU 是 `9900016534`（**不在菜单里**），核价 23.8 → 19.9，
>   **真实只省 ¥3.9**，不是标题暗示的 9.6。这个 SKU 已被补进菜单，否则用户拿着券却买不到东西。
>
> 算不了的券会明确标「需在结算页核销」，**不参与自动用券、也不计入立省**——宁可少报，不报假账。
> 另外：**一张券只对 1 件生效**（`quantity=2` 带券核价时接口会把数量截成 1），多件请拆开核价。

## 🚀 安装与使用（3 步）

### 第 1 步：申请 MCP Token

1. 打开 <https://open.mcd.cn/mcp> ，点击右上角【登录】
2. 使用手机号验证码登录
3. 点击右上角【控制台】→【激活】，申请 MCP Token
4. 同意服务协议后即可一键复制 Token

### 第 2 步：配置 MCP 连接器

在任意支持 Streamable HTTP 的 MCP Client（推荐 [WorkBuddy](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Connector)、Cursor、Cherry Studio、Trae）中填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

> ⚠️ 记得把 `YOUR_MCP_TOKEN` 替换为你的真实 Token，并妥善保管，切勿提交到任何仓库。

### 第 3 步：安装 Skill 并说话

把本仓库 `SKILL.md` 放入你的 Skill 目录，然后直接说：

| 你说                     | 助手做什么                                     |
| ---------------------- | ----------------------------------------- |
| 「我在深圳南山科技园，30 块怎么吃最划算」 | 定位门店 → 领券 → 枚举组合 → 输出省钱榜单 + 3 套方案 + HTML 可视化页 |
| 「20 块钱能吃到什么，要最划算的」    | 打开省钱榜单，套餐榜按 ≤¥20 筛，直接给券后最优组合                        |
| 「500 大卡能吃什么，要蛋白质高的」    | 按热量预算搭配，展示营养结构                            |
| 「我要自己配，巨无霸换板烧，薯条换玉米」   | 展示可替换项，实时算价算热量                            |
| 「就按方案 1 下单，外送」         | 核价 → `create-order` → 返回官方支付链接            |

## 🏗️ 技术实现

- **Skill 层**：`SKILL.md` 定义触发词与九阶段工作流（定位 → 领券 → 菜单/营养取数 → 场景搭配 → **省钱榜单** → 提醒 → 拼单 → 下单 → 商城订单），约束模型必须真实调用 MCP、禁止臆造数据。
- **数据层**：每次会话拉取一次 `query-meals` + `list-nutrition-foods`，合并为本地缓存映射。
- **推荐算法**：预算/热量约束下的组合枚举（贪心 + 剪枝），本地初筛后仅对 Top 3 调用 `calculate-price` 精算，单次会话 MCP 调用 < 10 次，规避 600 次/分钟限流。
- **省钱榜单算法**：`build_savings()` 用「现价 / 划线原价 / 券规则」三件套枚举主餐 × 饮品（× 小食），
  逐条套最优券后按 5 个维度排序；券规则统一解析为可计算对象（满减 / 折扣 / 直减 / 特价 N 元购 / N 元任选 M 件 / 免费换购），
  解析不出来的（如买一送一）宁可不进榜。支持 `build_data.py --rank` 离线重算，不联网、不产生编造数据。
- **可视化层**：单页 HTML，纯原生 JS 实现状态驱动渲染——选品、券开关、模式切换、门店选择全部实时联动「原价 / 立省 / 应付 / 总热量」。
- **闭环**：用户确认 → `create-order` → 麦当劳官方支付链接（本项目不接触任何支付信息）。

## ❓ 常见问题（FAQ）

**Q1：点开页面一片空白 / 只有一个深色背景？**
`order-assistant.html` 与 `data.js` **必须在同一个目录**。只下载了 HTML 就会白屏——请整个仓库一起下载，或直接用[在线版](https://huangxxuan.github.io/mcd-savings-skill/)。

**Q2：页面上的价格和店里不一样？**
页面读的是 `assets/data.js` 快照（**2026-10-20 21:37 抓取**），不是实时价格。要拉最新数据：
```bash
MCD_MCP_TOKEN=你的Token python3 scripts/build_data.py
```
跑完刷新页面即可。

**Q3：调用 MCP 报 401？**
Token 失效或没带对。去 <https://open.mcd.cn/mcp> 重新生成，确认 Header 是 `Authorization: Bearer <token>`。

**Q4：报 429 Too Many Requests？**
触发限流（600 次/分钟）。本项目正常使用不会超——菜单与营养数据每次会话只拉一次并本地缓存，只对 Top 3 组合调 `calculate-price`。若确实超了，等 1 分钟再试。

**Q5：点了「一键领券」，页面还显示「未领取」？**
`auto-bind-coupons` 成功后，查询接口有**短暂延迟**。等几秒刷新，或重跑 `build_data.py --claim`。这不是领取失败。

**Q6：为什么不直接在 GitHub 上点 `order-assistant.html`？**
GitHub 只显示源代码，不渲染 HTML。请用[在线版](https://huangxxuan.github.io/mcd-savings-skill/)，或下载后本地双击。

**Q7：应付金额为什么和「商品金额」不一样？配送费哪来的？**
页面**不写死配送费**。它只读门店返回的真实字段；门店接口没给，就不加钱，
HUD 直接写「不含配送费（以结算页为准）」。想看含配送费的准确金额，
复制页面底部的点单指令让 Agent 调 `calculate-price` 核价——那才是最终价。
切到「🍽 到店自取」，配送费和起送门槛都归零。

**Q8：别人装上这个 Skill，看到的是我的券吗？怎么换成自己的？**
你看到的是**生成 `assets/data.js` 那个 Token 账号**的券（页面顶部有数据来源说明条，写着快照时间）。
换成自己的只需一条命令——用**你自己的 Token** 重跑：
```bash
MCD_MCP_TOKEN=你的Token python3 scripts/build_data.py --claim
```
`--claim` 会先调 `auto-bind-coupons` 把能领的券领到你自己的卡包，再抓门店券、菜单、营养与账户余额。
`data.js` 一换，页面上所有券、金额、省钱榜单**自动跟着变，不需要改一行代码**。

**Q9：「不错过」板块里有的能点、有的点不了？**
规则是固定的：能在菜单里找到对应商品的券 → 可点，点了在菜单里高亮并闪烁；
待领券 → 点了跳到优惠券面板；找不到对应单品的 → 不可点，会写明「该券无对应单品，需在结算页核销」。
免费券如果只能模糊匹配到某个商品，会打上「近似」标记，**只用于定位，不会拿来抵扣金额**——
否则就会出现「免费券却按另一个商品的价格收你钱」。
这个板块的定位只有一件事：提醒你**快过期的券、能领没领的券、今日活动**，别错过。
